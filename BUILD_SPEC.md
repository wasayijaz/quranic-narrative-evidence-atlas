## 0. Non-negotiables

These are project constraints, not implementation preferences. Violating one is a build failure, not a style issue.

1. **Nothing is invented.** No claim, citation, grade, page number, date, chain, identification, or scholarly position may originate from the implementing agent. Every published statement resolves to a work, an edition, and a page or locator. If a person holding that edition cannot turn to that page and find it, it does not publish.
2. **The agent composes; it does not attest.** Drafted prose is a candidate. Only a human marking `located: yes` in the ledger converts a candidate into published content. The build enforces this; it is not a convention.
3. **No text under a non-commercial-only licence is ever committed to the repository.** The repository is public. Committing conditionally-licensed text relicenses it by accident. Public-domain text only. See [catalogue ?3](./OPEN_RESOURCES_CATALOG.md).
4. **Sunni and Shia are both primary.** Parity is enforced per claim. A tradition with no located source renders as a **labelled empty column**, never as silent omission and never as a filled column sourced from the other tradition.
5. **English and Urdu are equal from the first claim.** Urdu is composed natively. Machine translation is never published, and no Urdu string is ever generated by translating the English one.
6. **No human figures in any illustration.** No faces, bodies, silhouettes, or outlines. This includes icons, decorative art, and map markers.
7. **The site issues no rulings and holds no position.** It quotes and locates. Never "Sunnis believe" or "the Shia view is" ? only which named scholar, in which named work, on which page.

## 1. Scope of this build

**In scope ? the evidence foundation and first product slice:**

One dossier (`ashab-al-kahf`), adult reading depth only, English and Urdu, claim-level sourcing, verification ledger, a build that enforces the located gate, and the bilingual product surfaces listed in `PRODUCT_BUILD_SCOPE.md`. Ugly is acceptable. Correct is not optional.

**Explicitly out of scope. Do not build these.**

Database of any kind ? CMS ? authentication ? site search ? maps and route rendering ? footprint animation ? the illustration system ? other dossiers ? a design system beyond the tokens in ?7 ? mobile apps ? analytics ? comments ? newsletter ? a domain.

Adding anything from that list is scope violation, not initiative. If a task seems to require one, stop and ask.

## 2. Stack

| Layer | Choice | Reason it is not negotiable |
|---|---|---|
| Framework | **Astro** (latest stable) | Schema-validated content collections mean malformed content **fails the build natively**. Static HTML by default, so pages are indexable and hosting is free. Low API churn matters for a project maintained by one person over years |
| Content | **YAML files in git.** No database | Settled in [roadmap ?3](./ROADMAP.md). Content, sources, and verification records version together and move together |
| Validation | **Zod**, via Astro content collections | The schema is the gate's first half |
| Styling | Plain CSS with custom properties. No Tailwind, no CSS-in-JS | One maintainer, long horizon, minimal dependency surface |
| Client JS | **None by default.** Any interactive element must justify itself and degrade to working HTML | Static, indexable, accessible, cheap |
| Hosting | **Vercel**, free tier, deploying from a public GitHub repository | Decision 14 |
| Package manager | npm | Fewest moving parts |

**Version policy:** pin exact versions in `package.json`. No caret ranges. The build must be reproducible in two years.

**Owner workflow constraint that shapes everything:** the project owner does not write code and will edit files **through the GitHub web interface**. Every file a human is expected to touch must be readable and editable in a browser textarea by someone who has never used a terminal. That means flat YAML, no nesting beyond two levels in the ledger, no ids the human has to invent, and build errors phrased as sentences.

## 4. Schemas

Definitive shapes. Field names are fixed ? downstream documents reference them.

### 4.1 Source record ? `content/sources/*.yml`

One file per **edition**, not per work. An edition is the citable unit.

```yaml
id: tabari-jami-al-bayan
work_title_ar: "???? ?????? ?? ????? ?? ??????"
work_title_en: "Jami' al-Bayan 'an Ta'wil Ay al-Qur'an"
author: "Abu Ja'far Muhammad ibn Jarir al-Tabari"
author_died_hijri: 310
author_died_ce: 923
tradition: sunni              # sunni | shia | academic | shared
source_class: tafsir          # quran | hadith | tafsir | history | academic
edition:
  id: bulaq-amiriyya
  publisher: "Al-Matba'a al-Kubra al-Amiriyya"
  place: "Bulaq, Egypt"
  language: ar
  volumes: null               # null when unconfirmed ? never guessed
rights:
  status: public-domain       # public-domain | non-commercial | permission-required | unknown
  basis: "Author died 310 AH. Work is out of copyright in all relevant jurisdictions."
  redistributable: false      # scan-holder terms are separate from the work's status
access:
  kind: page-images           # page-images | printed | paginated-text | text-no-pagination
  locator: "archive.org/details/dli.ernet.431838"
  scanned_by: "C-DAC Noida, from Maulana Azad Library, Aligarh Muslim University"
  collection: "Digital Library of India"
  notes: "PDF and single-page-processed JP2 ZIP available."
```

**Enforced rules:**

- `access.kind: text-no-pagination` makes the source **ineligible for citation**. A page number cannot come from unpaginated text. Such a source may be recorded for discovery use, but the gate rejects any attribution pointing at it.
- `rights.status: unknown` or `non-commercial` ? the source may be cited but **its text may never be committed to the repository**. The build must refuse a source file containing a `full_text` field. There is no such field. Do not add one.
- `redistributable: false` means page images are not to be committed or re-hosted. Cite by locator.

Two source files exist at start; both are already researched in [catalogue ?3b](./OPEN_RESOURCES_CATALOG.md). Do not invent a third.

### 4.2 Claim record ? `content/dossiers/<dossier>/claims/*.yml`

One claim per file. The claim is the centre object; every surface renders it.

```yaml
id: ak-014
statement:
  en: "?"
  ur: "?"
status: disputed              # attested | disputed | reported-only | rejected
source_class: tafsir
independence_group: g-ephesus-identification   # optional; groups non-independent attestations

attributions:
  - source: tabari-jami-al-bayan       # must match a source id
    edition: bulaq-amiriyya            # must match that source's edition id
    volume: 15
    page: 197
    tradition: sunni
    quote_ar: "?"                      # the located words, verbatim
    quote_en: "?"                      # translation, attributed in the manifest
    quote_ur: "?"
  - source: tabarsi-majma-al-bayan
    edition: ministry-of-culture-9pt
    part: 6
    page: 312
    tradition: shia
    quote_ar: "?"

evaluation:                   # attributed evaluations only. Never the site's own.
  - grade: "mawdu'"
    critic: "?"
    stated_in:
      source: ?
      edition: ?
      page: ?

supersedes: null              # id of a claim this replaces
superseded_by: null
```

**Enforced rules:**

- `evaluation[].grade` **must** carry both `critic` and `stated_in`. A bare grade string is exactly the grade-drift failure in [the intake system](./RESOURCE_INTAKE_SYSTEM.md) ?1. Schema rejects it.
- `statement.en` and `statement.ur` are both required. Neither may be empty. A claim with only one language does not exist.
- Every `attributions[].source` and `.edition` must resolve to a real source record. Dangling reference fails the build.
- `page` is required unless the source's `access.kind` legitimately has no pagination ? in which case the source was ineligible anyway.
- A claim may carry attributions from one tradition only. That is normal and is **not** an error. It renders as a labelled empty column and increments the parity-gap count.

### 4.3 Ledger ? `content/dossiers/<dossier>/ledger.yml`

**This is the only file the project owner edits regularly.** Optimise it for a non-technical human editing in a browser. Flat list, one block per row, no nested structures, no invented identifiers.

```yaml
- claim: ak-014
  source: tabari-jami-al-bayan
  edition: "Bulaq/Amiriyya, vol 15, p 197"
  located: no                 # yes | no | secondary
  checked_by: ""
  date_checked: ""
  notes: ""
  superseded_by: null
```

**Enforced rules:**

- `located: yes` requires `checked_by` and `date_checked` to be non-empty. The schema rejects a bare yes.
- **Rows are never deleted.** Corrections add a new row and set `superseded_by` on the old one, with the reason in the new row's `notes`. The public correction log is generated from superseded rows.
- One row per **(claim, source)** pair, not per claim. A claim citing two editions needs two rows, and both must be located before it publishes.

## 5. The gate

Two distinct failure modes. Keeping them distinct is the entire discipline: **forgetting is loud, not-yet-checked is quiet but public.**

| Condition | Build behaviour | Rationale |
|---|---|---|
| Claim attribution has **no matching ledger row** | **Hard build failure**, naming the claim and source | Nobody decided anything here. It is an oversight, and oversights must not be survivable |
| Ledger row exists, `located: no` | **Claim withheld from render.** Counted in the public "unlocated" figure | Working as designed. Honest, visible, not an error |
| Ledger row `located: secondary` | Claim **publishes with a visible label**. Counted separately in the public figures | The middle state must stay visible rather than rounding up to verified |
| Ledger row references a claim or source that does not exist | **Hard build failure** | Referential rot |
| Claim publishes with only one tradition attributed | Publishes. Increments **parity-gap** count, renders labelled empty column | Decision 15 |

**Implementation requirements:**

- Gate logic lives in exactly one module, `src/lib/gate.ts`. No page, component, or script may re-implement or bypass it.
- `scripts/check.mjs` runs on `prebuild` and exits non-zero on any hard failure. Vercel's build then fails and the deploy does not ship.
- **Error messages are written for a non-programmer.** Not `Error: undefined reference at index 4`. Instead: `Claim ak-014 cites al-Tabari, Bulaq/Amiriyya vol 15 p 197, but ledger.yml has no row for it. Add a row with located: no.`
- The gate is **fail-closed**. Any state the logic does not recognise withholds the claim. Never publish on an unrecognised value.

## 6. Rendering requirements

**Pages required by this slice ? nothing more:**

1. `/en/ashab-al-kahf` and `/ur/ashab-al-kahf` ? the dossier, claims in order, each with its attributions visible.
2. `/en/verification` and `/ur/verification` ? the derived global ledger view, **including the gaps**: total claims, located, secondary, unlocated, parity gaps. The number that matters is how many are unverified, and it stays on the page.

The current product layer additionally renders `/en|ur/` (Explore), `/en|ur/quran` (Quran passage anchors), `/en|ur/learn` (Story Canvas), `/en|ur/teach` (local Teacher Studio), and `/en|ur/research` (Evidence Desk). These routes may compose Quran references and ledger metadata, but they must not bypass the gate or publish an unlocated claim statement.

**Hard requirements:**

- **Static output.** Server-rendered at build, fully indexable, no client-side routing.
- **Both languages are first-class routes.** No language detection, no redirect, no cookie. `/ur/?` is a real page with real Urdu content.
- **Correct bidi isolation.** Arabic quotations inside English prose, and English or Latin identifiers inside Urdu prose, must be isolated (`dir` attributes and `bdi` where appropriate). Mixed-direction text that renders scrambled is a defect, not a polish item.
- **`lang` and `dir` set correctly** on `html` and on any element whose language differs from its parent.
- **WCAG 2.2 AA.** Contrast, focus visibility, heading order, landmark structure, keyboard reachability. Verify, do not assume.
- **Every claim shows its source class, its status, and its verification state** without the reader clicking anything. Those are three of the four independent axes; they are never merged into one badge.
- **`prefers-reduced-motion` respected.** In this slice there should be no motion to reduce.

**Never render:**

A claim with no located attribution ? a grade without its critic and locator ? a tradition column filled from the other tradition's source ? an inferred page number ? a language string derived by translating the other language.

## 7. Tokens and typography

Palette ? from [DESIGN.md](./DESIGN.md), which is authoritative if it disagrees:

```css
:root {
  --paper:      #F7F3EA;
  --ink:        #18211F;
  --quran:      #1F6B57;   /* emerald  */
  --hadith:     #315F86;   /* sapphire */
  --tafsir:     #9A641F;   /* ochre    */
  --history:    #944B3C;   /* clay     */
  --hypothesis: #665887;   /* violet   */
  --unknown:    #68736F;   /* slate    */
}
```

Colour encodes **source class** only. It never encodes verification state ? that is a separate axis and must have a separate visual channel. Never rely on colour alone; every colour-coded distinction carries a text label.

**Fonts:** self-hosted, open-licensed, committed to `/public/fonts` with their licence files. Urdu requires a Nastaliq face; Arabic requires a Naskh face. Confirm the specific choices against [DESIGN.md](./DESIGN.md) ?8 before adding files, and record each font's licence in the repository. Nastaliq has extreme line-height requirements ? test Urdu paragraphs at real length, not with placeholder strings.

## 8. Task sequence

Each task has an acceptance test. Do not begin the next until the current one passes.

**Task 1 ? skeleton and gate, with no content at all.**
Astro project, content collections defined, Zod schemas from ?4, `scripts/check.mjs` wired to `prebuild`, Vercel deploying from the public repo.
*Accept when:* a deliberately malformed YAML file fails the build with a human-readable message, and removing it makes the build pass. Nothing is published yet.

**Task 2 ? the two source records.**
`tabari-jami-al-bayan.yml` and `tabarsi-majma-al-bayan.yml`, transcribed from [catalogue ?3b](./OPEN_RESOURCES_CATALOG.md). Nothing invented; unknown fields stay `null`.
*Accept when:* both validate, and a claim citing a non-existent edition id fails the build.

**Task 3 ? one claim, end to end.**
One claim from Ashab al-Kahf, English and Urdu, at least one attribution, ledger row created with `located: no`.
*Accept when:* the claim is **withheld** and appears in the unlocated count; flipping the row to `located: yes` with `checked_by` and `date_checked` publishes it; removing the row entirely fails the build. All three states verified.

**Task 4 ? the verification page.**
Derived global view with gaps published.
*Accept when:* counts match the files, in both languages, and a superseded row renders in the correction log.

**Task 5 ? ten claims.**
Then stop and report measured cost per claim. That measurement is [what M0 exists for](./ROADMAP.md).

## 9. Standing constraint on the implementing agent

Draft prose, propose claim structure, locate candidate passages, and build everything above. Do not mark anything `located: yes`. Do not fill `checked_by`. Do not supply a page number, volume number, edition detail, date, or grade from memory or inference ? if it was not read off the actual source, the field stays empty and the claim stays unpublished.

The failure to expect is not obvious nonsense. It is fluent, mostly-correct text carrying a citation that looks checkable and is subtly wrong. Reading well detects none of it.

> **Fluency is not evidence. The only check that counts is opening the cited edition and finding the page.**

## 10. One open assumption

Both source editions are unvocalised classical Arabic page scans with no text layer. The build assumes a human who can read them will perform the `located` checks. If that assumption fails, the source list changes ? toward paginated critical editions in a readable language ? but **the architecture above does not change**. Build it either way.
